## Принятые задачи

### 1. Контракт серверного профиля — заблокирован спецификацией API

**Уже сделано:** на экране профиля есть свёрнутая панель статистики, селектор
сервера из каталога (первоначально выбран текущий/последний открытый сервер),
поля блоков, убийств мобов/игроков и смертей, а также отдельные группы
Minecraft Advancements и достижений модов. Пока показано только честное пустое
состояние — запросов и демонстрационных значений нет.

**Зафиксированные решения:** общий endpoint провайдера ориентировочно
`GET /launcher/servers/{server_id}/profile`, авторизация существующей сессией;
фракции могут быть доступны только по явному флагу конкретного сервера;
источником фракционных данных будет серверный мод. Карточка фракции краткая:
название группы, роль игрока и число участков, без списка участников.

**Перед подключением API нужно согласовать:** точную схему успешного ответа,
пустого профиля и ошибок; правила неизвестных/недоступных серверов и прав;
название и тип конфигурационного флага фракций; политику версионирования и
кэширования. Не добавлять endpoint, поля ответа, mock-метрики и UUID-поля
самостоятельно.

**Идентификация:** UUID аккаунта связывает с серверным модом при первом
подтверждённом входе по одноразовому launch-ticket. Не передавать UUID из
интерфейса лаунчера и не вычислять личность из имени игрока. Точная транзакция
привязки и ошибки должны быть частью согласованного контракта мода/провайдера.
Старый черновик в `SESSION-MODEL-A.md` не является утверждённой спецификацией
для новой привязки; см. его предупреждение и [PROVIDER.md](PROVIDER.md).

**Критерий завершения:** контракт документирован и протестирован на reference
provider; интерфейс показывает loading/empty/error и данные только из реального
ответа; фракционный раздел скрыт при отсутствующем/ложном флаге; ошибки
авторизации и сервера не маскируются пустыми счётчиками.

### 2. Minecraft/Prism: безопасный план установки и восстановления

**Не завершено:** типичный экспорт Prism без Mojang version profiles пока можно
описать и проверить на совместимость, но нельзя полностью установить и
восстановить. ZIP-подтверждение пока не является точным списком всех файлов и
может появиться после загрузки архива или части компонентов.

**Работа:** сформировать revision-bound план по проверенным метаданным; точно
перечислить недостающие/повреждённые компоненты, источники и известные размеры;
попросить согласие до загрузки дополнительных компонентов; после согласия
перепроверить ревизию и план, загрузить только нужное, проверить хеши, сохранить
исправные данные и атомарно опубликовать результат. Не выполнять команды и Java
пути из метаданных. Для неопознаваемых или непроверяемых файлов — отказ с
диагностикой, а не доверие по имени/каталогу.

**Критерий завершения:** реальные Prism-экспорты с профилем и без него проходят
чистую установку, повтор, ремонт и отказ от consent; отказ не начинает
несогласованные component downloads; миры/настройки сохраняются. Подробный
текущий аудит и матрица сценариев — [INSTALLATION-AUDIT.md](INSTALLATION-AUDIT.md).

### 3. Connector и прочие производные файлы

Проверка может подтвердить неизменённый вложенный Fabric JAR по хешу
поставляемого родительского мода и его декларации. Неизвестные, преобразованные,
неоднозначные или изменённые артефакты остаются заблокированы; их нельзя
разрешать только по пути и нельзя автоматически удалять.

**Работа:** на реальных поддерживаемых версиях Connector/лоадеров подтвердить
происхождение таких файлов; для непроверяемых артефактов спроектировать безопасное
восстановление или отдельное согласие с точным объяснением. Проверить бюджет
чтения, гонки, симлинки/reparse points и Windows. До этого не обещать полную
совместимость с Connector. См. [INSTALLATION-AUDIT.md](INSTALLATION-AUDIT.md).

### 4. Проверка реальной установки и платформ

Локальные TypeScript-тесты, pure-Rust harness и браузерные заглушки не равны
полному Cargo build или запуску игры. В текущей среде нет `rustc`, `cargo` и
`javac`; Windows, WebView2, реальные установщики и настоящий Minecraft не
проверены.

**Работа:** на Windows выполнить полный locked Cargo test/Clippy и desktop build;
проверить чистую и повторную установку, ZIP/packwiz/Modrinth, Prism repair,
Connector, Java/лоадеры, consent/refusal, отмену/прерывание, конкурентные
процессы, миры/настройки и WebView2. Отдельно проверять поведение файловой
системы после ошибки и завершения процесса; не заявлять power-loss safety без
соответствующего испытания. Сверяться с матрицей в
[INSTALLATION-AUDIT.md](INSTALLATION-AUDIT.md) и актуальным журналом
[VERIFICATION.md](VERIFICATION.md).

### 5. Открытые ограничения загрузок и Minecraft lifecycle

- Лимит скорости сейчас не охватывает все загрузки Minecraft, Java и внешних
  установщиков; отмена и прогресс у сторонних механизмов имеют отдельные
  границы.
- Выполнить измерения времени, CPU/диска, сетевых байтов и повторно используемых
  файлов на одинаковой машине и сборке до оптимизаций.
- Проверить отмену/закрытие лаунчера и дочерних операций, долгие blocking tasks,
  блокировки и восстановление; сообщения UI не должны объявлять готовность до
  фактического завершения.

Подробный список проверок оболочки/экрана сохранён в
[UI-AUDIT-ACTIONS.md](UI-AUDIT-ACTIONS.md); исследовательские предложения по
архитектуре загрузчика — в [LAUNCHER-REFACTOR-RESEARCH.md](LAUNCHER-REFACTOR-RESEARCH.md).
Они не являются разрешением на массовый рефакторинг: сначала измерить и
согласовать объём.

## Отложено, не входит в принятый план

- **CurseForge:** нет реализации. До отдельного решения проверить права
  распространения, API-ключи, rate limit, прокси и UX недоступного файла;
  обходить ограничения или вшивать секрет в лаунчер нельзя.
- **Единая очередь скачивания, глобальный кэш, mirrors, Range/resume,
  перезапись `mc-launcher-core`:** идеи из исследования, а не утверждённые
  задачи. Требуются конкретные замеры, контракт безопасности, лицензии и
  отдельное согласование.
- **Подпись приложения, собственный updater, подпись конфигурации/манифестов и
  модерационные API:** не входят в текущий контракт и не должны появляться
  автоматически. До релиза отдельно определить модель доверия, ключи и
  ротацию, распространение, поддержку и ответственность провайдера; подписанный
  config/manifest и API банов/модерации добавлять только при подтверждённой
  B2B-потребности.
- **LineAuth:** `SESSION-MODEL-A.md` и `LINEAUTH-AUDIT-PROMPT.md` содержат
  подробный прежний проектный черновик и аудит, но не доказывают готовность
  мода/провайдера. Текущие выбранные правила UUID-привязки перечислены в задаче
  1; противоречащие черновые положения не использовать без повторного
  согласования.
