# Демо-режим: проверить лаунчер целиком

Одна команда поднимает **локальный демо-провайдер** и запускает **настоящее
приложение** — со входом, установкой, запуском Java-процесса, гардеробом и
настройками. Ничего не нужно вводить руками: адрес вшивается на время демо,
сертификат доверяется только этому процессу, при выходе всё возвращается как было.

```sh
npm ci
npm run demo:doctor    # что не хватает на этом компьютере (ничего не меняет)
npm run demo           # провайдер + окно приложения
```

Первый запуск собирает Rust — это может занять несколько минут. Дальше окно
открывается само. Программы ставятся по шагам в **[BUILD.md](BUILD.md)** (шаг 1),
там же — разбор частых ошибок.

Если удобнее видеть лог провайдера отдельно, используйте два терминала:

```sh
npm run demo -- --provider-only   # терминал 1: только провайдер
npm run demo:app                  # терминал 2: окно приложения
```

`demo:app` сам найдёт провайдера и подставит сертификат — вводить переменные
окружения не нужно ни в Windows, ни в macOS, ни в Linux.

## Проверка BattleArmory в одиночном мире

```powershell
npm run demo -- --battlearmory
```

Войдите как `Player_1` / `demo-password`, откройте **BattleArmory — тестовый
режим** и нажмите **«Тестовый режим»**. Лаунчер скачает настоящую сборку и
необходимые компоненты Minecraft, затем должен открыть меню игры; создайте
одиночный мир вручную. Адрес `127.0.0.1:25565` в демонстрационном конфиге —
только заглушка: сервер не запускается, обычная кнопка «Играть» не проверит
сетевой сервер. Игра и её миры сохраняются в данных лаунчера после выхода из
демо. Команда может скачать сотни мегабайт и требует свободного места; выполнение
этого сценария на Windows ещё не подтверждено. Демоверсия использует локальный
провайдер и dev-сертификат, не предназначенный для выпуска.

## Где смотреть, что произошло

- **Консоль провайдера** (там же, где вы запустили `npm run demo`): `login`,
  `register`, `ticket issued`, `exchange accepted`, `skin updated`, `skin reset`.
  Каждый отказ обмена пишется с причиной — это готовый оракул для проверки.
- **Лог игры**: `<app-data>/instances/<сервер>/logs/launch.log` — вывод самой
  демо-«игры», включая результат обмена. Перезаписывается при каждом запуске.
- **Данные лаунчера**: `<app-data>/instances/` — установленные релизы и история.

Каталог `<app-data>`:

| ОС      | Путь                                                            |
| ------- | --------------------------------------------------------------- |
| Windows | `%APPDATA%\studio.plusinplus.line-launcher`                     |
| macOS   | `~/Library/Application Support/studio.plusinplus.line-launcher` |
| Linux   | `~/.local/share/studio.plusinplus.line-launcher`                |

## Обновление и откат

Демо собирает два релиза Demo Survival. Пока провайдер работает:

```sh
npm run demo:update    # 1.0.0 → 1.1.0 и обратно
```

В лаунчере: «Переподключиться» → «Установить сборку» → «История сборок» → откат.
Предыдущий релиз остаётся доступным, поэтому откат проверяется по-настоящему.

## Проверка защиты файлов руками

Каждый сервер ставится в свой каталог, а файлы сверяются с индексом sha256 при
каждом запуске. Проверить это можно без всяких инструментов:

1. Установите Demo Survival и найдите каталог
   `<app-data>/instances/demo/releases/<длинный sha256>/`.
2. Создайте там папку `mods` и положите в неё любой файл — это «посторонний мод».
3. Нажмите «Играть»: под кнопкой появится «Проверка файлов: удалено посторонних —
   1», файл исчезнет, запуск продолжится.
4. Теперь измените `client.jar` (например, допишите байт) и снова нажмите
   «Играть»: лаунчер скачает сборку заново и только потом запустит её.
5. Каталог `instances/demo/game/` при этом не тронут — там миры и настройки.

Что именно проверяется и почему — [GAME.md](GAME.md).

## Проверка без окна приложения

```sh
npm run demo:check
```

Прогоняет весь контракт демо по настоящему HTTPS: схему конфига, опубликованные
хеши и размеры, оформление, один аккаунт на все серверы, гардероб, одноразовые
ticket и публикацию второго релиза. Нужны только Node и openssl — ни JDK, ни
Rust, ни окно. Полезно, когда `npm run demo` не запускается и надо понять, на
чьей стороне проблема.

## Если не работает

| Симптом                                    | Причина и что делать                                                                             |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| «Окружение не готово… нет Rust»            | `npm run demo:doctor` напишет, чего нет; установка — [BUILD.md](BUILD.md), шаги 1–2              |
| «Провайдер не запустился на порту 8443»    | порт занят: `npm run demo -- --port 8453`; кто занял — покажет `npm run demo:doctor`             |
| «Компилятор Java не найден»                | демо без запуска игры. Поставьте JDK 17+ или задайте `JAVA_HOME`, затем повторите `npm run demo` |
| В окне «Не удалось проверить сертификат»   | приложение запущено не через демо. Используйте `npm run demo` — он подключает сертификат сам     |
| macOS: в консоли «trusting only … root(s)» | это нормально: на macOS демо-сборка доверяет только локальному сертификату, keychain не меняется |
| Сертификат истёк (демо стояло месяц)       | ничего делать не нужно: провайдер сам выпустит новый при следующем запуске                       |
| Список серверов не грузится                | провайдер остановлен или порт другой; смотрите его консоль                                       |
| Хочу начать с чистого листа                | остановите демо, удалите `.provider/` и каталог `instances` в app-data                           |
| Хочу посмотреть только интерфейс, без Rust | `npm run test:ui` — сквозной прогон UI в Chrome/Edge с подменённым IPC (Rust не нужен)           |

## Как это устроено

- `scripts/demo.mjs` — оркестратор: проверки окружения → сборки → брендинг →
  провайдер → приложение → возврат `branding/provider.json` при выходе.
  Режим `--app-only` (`npm run demo:app`) читает `.provider/demo-state.json`,
  который оставляет работающий `--provider-only`, и запускает только окно.
- `scripts/demo-doctor.mjs` — диагностика всей цепочки без изменений в файлах.
- `scripts/lib/demo-cert.mjs` — выпускает локальный сертификат и **перевыпускает**
  его, если срок истёк, часы сбиты или адрес не подходит. Просроченный файл больше
  не переиспользуется молча.
- `examples/provider/build-pack.mjs` — три сервера, два релиза, оформление и
  готовые скины; всё детерминированно, без бинарников в репозитории.
- `examples/provider/server.mjs` — HTTPS-провайдер: вход, регистрация, гардероб,
  одноразовые ticket, обмен. Аккаунты в памяти, **не для production**.
- `examples/provider/publish-release.mjs` — публикует второй релиз на ходу.
- Cargo-фича `dev-provider-ca` добавляет локальный сертификат **только процессу
  лаунчера**. Она выключена по умолчанию и не должна попадать в распространяемую
  сборку; `npm run demo` никогда не собирает установщик.

Демо — разработка, а не образец безопасности: пароль сравнивается напрямую,
ticket лежат в `Map`, сертификат самоподписанный. Контракт протокола — тот же,
что у боевого провайдера: [PROVIDER.md](PROVIDER.md).

## Новые проверки подключения и Java

- Демо обходит системный proxy/VPN для локального соединения. Если сервер всё же
  отвечает `HTTP 302 без Location`, проверьте, что `config.json` отдаёт JSON
  напрямую, и перезапустите `npm run demo`.
- Если Java установлена, но автоматический список пуст, откройте «Настройки →
  Java», повторите поиск или укажите полный путь к `java.exe`/папке JDK. Кнопка
  «Проверить и выбрать» покажет результат настоящего `java -version`.

## Оформление и песочница дизайна

Демо запускает **ту же** сборку интерфейса, что и обычный запуск: `npm run demo`
вызывает `tauri dev`, а тот — `beforeDevCommand: npm run dev`, то есть Vite
отдаёт `src/index.tsx` со всеми изменениями. Отдельного «демо-дизайна» нет.

Что стоит знать, если «изменений ноль»:

1. **Нужен свежий чекаут.** Демо собирает Rust и фронтенд из текущей папки:
   ```
   git fetch origin && git status --short   # должно быть пусто
   git switch main && git pull              # или своя ветка
   npm ci                                   # зависимости могли измениться
   npm run demo
   ```
   Если `git status` показывает чужие правки, `git reset --hard origin/main`
   вернёт ровно то, что в репозитории.
2. **Сборка Rust не перезапускается от правок CSS.** После смены зависимостей
   или `Cargo.toml` первый `npm run demo` может идти несколько минут — это
   нормально, окно появится позже.
3. **Оформление не переключается.** Дизайн один; то, что игрок может изменить, —
   это **фон**: «Настройки → Фон лаунчера», двенадцать градиентов с мгновенным
   предпросмотром. Выбор сохраняется и переживает перезапуск.
4. **Посмотреть интерфейс без Rust и без провайдера:**
   ```
   npm run dev
   ```
   Откроется пустое окно — настоящий лаунчер требует Tauri IPC. Чтобы увидеть
   все экраны с демо-проектом, запустите `npm run demo` (см. выше) или снимите
   галерею: `npm run screenshots` (нужен Chrome/Edge).

## Личные секции серверов

В списке серверов нажмите «Добавить секцию». В меню «…» у новой секции
выберите «Переименовать» и задайте имя, например «Избранное». Откройте Demo Survival и в поле «Секция» выберите её; вернитесь
в список и проверьте, что сервер оказался в новой секции. Альтернативный способ:
зажмите карточку сервера и перетащите её на заголовок другой секции или
«Без секции». Можно перетащить и в свёрнутую секцию; порядок карточек внутри
секции пока определяется провайдером. Выбор на странице сервера остаётся
доступен для клавиатуры и тех, кому неудобно перетаскивание. Заголовок секции
позволяет свернуть, переименовать или удалить её: удаление секции возвращает
серверы в «Без секции», а не удаляет сборки. После перезапуска демо настройка
должна сохраниться. Секции принадлежат игроку и хранятся в настройках лаунчера;
демо не перезаписывает существующую раскладку автоматически.

Кнопка «Проверить ресурс-паки» проверяет именно содержимое ресурс-паков, а не
всю сборку. Для ещё не установленной сборки она должна предложить сначала её
установить. Проверка целостности файлов релиза выполняется отдельно перед
запуском; ручное удаление подозрительных ресурс-паков пока остаётся за игроком.

## Если не запускается сборка интерфейса

Команды npm нужно выполнять из папки проекта, где находится `package.json`.
Для сборки из исходников нужны и зависимости разработки:

```powershell
cd D:\Проекты\Line-Launcher
npm ci --include=dev
npm run demo:doctor
```

Стили shadcn теперь хранятся в проекте; пакет `shadcn` для сборки не нужен.
Если диагностика сообщает о других отсутствующих файлах, пришлите полный текст
ошибки. Не публикуйте приватные npm-конфигурации или токены.
