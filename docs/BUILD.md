# Сборка лаунчера с нуля

Инструкция для человека, который раньше не собирал настольные приложения.
Идём по шагам сверху вниз, каждый шаг заканчивается проверкой «получилось или
нет». Ничего не нужно знать заранее.

- **Часть A — «просто посмотреть»** (шаги 1–3): запускаете готовое демо и щёлкаете
  все функции. Свой сервер не нужен.
- **Часть B — «сделать свой лаунчер»** (шаги 4–6): меняете название, логотип, адрес
  своего проекта и собираете установщик для игроков.

Первая сборка Rust занимает **5–20 минут** и качает несколько сотен мегабайт —
это нормально и происходит один раз. Дальше запуск занимает секунды.

> Застряли? Выполните `npm run doctor` (для приложения) или `npm run demo:doctor`
> (для демо). Они пишут, чего именно не хватает и какой командой это поставить.

## Шаг 1. Установить программы

### 1.1. Что нужно и зачем

| Программа                       | Зачем                                               | Обязательна                |
| ------------------------------- | --------------------------------------------------- | -------------------------- |
| **Node.js 22+**                 | интерфейс, сборка, демо-провайдер                   | да                         |
| **Git**                         | скачать проект; в Windows заодно даёт `openssl`     | да                         |
| **Rust (rustup)**               | собрать настольное приложение                       | да, для окна и установщика |
| **Системные зависимости Tauri** | компилятор и окна ОС (шаг 1.3)                      | да                         |
| **JDK 21**                      | собрать демо-«игру», чтобы работала кнопка «Играть» | только для демо с запуском |
| **openssl**                     | локальный HTTPS-сертификат демо                     | только для демо            |

### 1.2. Node.js и Git

**Windows.** Скачайте установщики и нажимайте «Далее»:

- Node.js 22 LTS — <https://nodejs.org/ru/download>
- Git for Windows — <https://git-scm.com/download/win>

**macOS.** В терминале:

```sh
xcode-select --install          # компилятор и git (окно установки)
# Node.js — установщиком с https://nodejs.org/ru/download
```

**Linux (Ubuntu/Debian).**

```sh
sudo apt update
sudo apt install -y git curl openssl
# Node.js 22 LTS:
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs
```

**Проверка.** Откройте **новый** терминал (PowerShell на Windows) и выполните:

```sh
node --version      # должно быть v22.x или новее
git --version
```

> **Важно про Windows.** Все команды ниже выполняйте в **PowerShell** или в
> терминале VS Code. После установки любой программы **закрывайте и открывайте
> терминал заново** — иначе он не увидит новые команды в `PATH`.

### 1.3. Rust и системные зависимости

**Windows.**

1. Установите **Visual Studio Build Tools** —
   <https://visualstudio.microsoft.com/visual-cpp-build-tools/>.
   В установщике отметьте рабочую нагрузку
   **«Разработка классических приложений на C++»**
   (англ. _Desktop development with C++_). Без неё Rust не сможет собрать `.exe`.
   Занимает несколько гигабайт.
2. Установите Rust — <https://rustup.rs> → скачайте `rustup-init.exe` → запустите →
   нажмите Enter на стандартном варианте.
3. **WebView2 Runtime** — в Windows 11 уже есть. Если окно не открывается:
   <https://developer.microsoft.com/microsoft-edge/webview2/> → _Evergreen
   Bootstrapper_.

**macOS.**

```sh
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
# затем перезапустите терминал
```

**Linux (Ubuntu/Debian).**

```sh
sudo apt install -y libwebkit2gtk-4.1-dev build-essential curl wget file \
  libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

**Проверка (новый терминал):**

```sh
rustc --version     # rustc 1.9x.x
cargo --version
```

### 1.4. JDK — только если хотите нажимать «Играть» в демо

Поставьте **JDK 21** (например, Eclipse Temurin —
<https://adoptium.net/temurin/releases/?version=21>). Нужен именно **JDK**, а не
JRE: демо-«игра» компилируется на вашем компьютере.

После установки задайте `JAVA_HOME`, если установщик не сделал этого сам, и
проверьте:

Если doctor видит Java, а список рантаймов в приложении пуст, откройте
«Настройки → Java → Повторить поиск Java». Можно также вставить полный путь к
`java.exe`, папке `bin` или JDK и нажать «Проверить и выбрать»: например,
`C:\Program Files\Eclipse Adoptium\jdk-25.0.3.9-hotspot\bin\java.exe`.
Лаунчер выполнит `java -version` и покажет точную причину отказа. Переустанавливать
уже работающий JDK не нужно. Выбранный рантайм сохраняется и перепроверяется при
запуске; версия должна совпадать с `java_major` сборки.

```sh
java -version
javac -version      # если этой команды нет — установлен JRE, а не JDK
```

Без Java демо **всё равно работает**: вход, установка, обновление, откат,
гардероб, настройки. Кнопка запуска будет честно выключена.

## Шаг 3. Запустить демо и проверить все функции

Демо поднимает **локальный демо-провайдер** (три сервера, два релиза, скины,
регистрация, вход) и открывает **настоящее приложение**. Никакие ссылки вводить
не нужно, сертификат доверяется только этому процессу, система не изменяется.

```sh
npm run demo:doctor    # проверка: чего не хватает именно для демо
npm run demo           # провайдер + окно приложения
```

Что происходит по шагам: проверка окружения → сборка демо-сборок → адрес
провайдера временно вшивается в сборку → запуск HTTPS-провайдера → запуск
приложения. **При выходе (Ctrl+C или закрытие окна) файл `branding/provider.json`
возвращается к прежнему содержимому байт в байт.**

Готовый аккаунт: **`Player_1` / `demo-password`**. Можно зарегистрировать свой.

Что нажимать внутри приложения — пошаговый чек-лист в **[DEMO.md](DEMO.md)**.

### Два терминала (удобно при разработке)

Если хотите видеть лог провайдера отдельно от лога приложения:

```sh
# терминал 1
npm run demo -- --provider-only

# терминал 2
npm run demo:app
```

`demo:app` сам найдёт запущенного провайдера и подставит сертификат — никаких
переменных окружения вводить не нужно (это работает одинаково в Windows, macOS и
Linux).

### Полезные варианты

| Команда                       | Что делает                                                    |
| ----------------------------- | ------------------------------------------------------------- |
| `npm run demo -- --port 8553` | другой порт, если 8443 занят                                  |
| `npm run demo -- --no-java`   | собрать демо без Java-компилятора                             |
| `npm run demo:update`         | выпустить версию 1.1.0 на ходу → проверить обновление и откат |
| `npm run demo:check`          | 59 автоматических проверок демо-провайдера по HTTPS           |
| `npm run demo:doctor`         | диагностика без изменений в файлах                            |

## Шаг 4. Сделать лаунчер своим: какие файлы менять

Всё, что нужно поменять владельцу проекта, лежит в **двух файлах** и папке с
картинками. Код компонентов трогать не нужно.

### 4.1. Карта файлов

| Файл                                                       | Что это                                           | Менять?                     |
| ---------------------------------------------------------- | ------------------------------------------------- | --------------------------- |
| `branding/provider.json`                                   | адрес `config.json` вашего проекта                | **да, обязательно**         |
| `branding/line.brand.json`                                 | название, цвета, логотип, издатель, идентификатор | **да**                      |
| `branding/assets/logo.svg`                                 | знак в шапке и в меню                             | да, на свой                 |
| `branding/assets/app-icon.svg`                             | исходник иконки приложения (1024×1024)            | да, на свой                 |
| `package.json`                                             | версия npm-пакета и команды                       | только `version`            |
| `src-tauri/Cargo.toml`                                     | версия Rust-приложения                            | только `version`            |
| `src-tauri/tauri.conf.json`                                | версия бандла, размер окна, CSP                   | `version`, размер окна      |
| `src/brand/generated.*`, `src/brand/provider.generated.ts` | **создаются командой** `npm run brand`            | **нет**                     |
| `src-tauri/tauri.brand.conf.json`, `src-tauri/icons/*`     | **создаются генератором**                         | **нет**                     |
| `src/`, `src-tauri/src/`                                   | код приложения                                    | нет, если не меняете логику |
| `examples/`, `scripts/`, `docs/`                           | демо-провайдер, инструменты, документация         | нет                         |

Правило простое: **если в имени файла есть `generated` или он лежит в
`src-tauri/icons` — руками его не правят.** Генератор перезапишет изменения.

### 4.2. Адрес вашего проекта — `branding/provider.json`

Это самое главное. Один лаунчер = один проект. Список серверов приезжает из
вашего `config.json`, а не хранится в лаунчере.

```json
{
  "config_url": "https://launch.example.com/line/config.json"
}
```

Требования: только `https://`, без логина/пароля в ссылке, без `#`, до 2048
символов.Другие ключи кроме `$comment` — ошибка.

- **пусто** (`""`) — это ненастроенный шаблон: в режиме разработки появится поле
  ссылки, а сборка установщика будет **остановлена** с понятной ошибкой;
- **заполнено** — приложение подключается само, игрок только регистрируется или
  входит.

### 4.3. Название, цвета, логотип — `branding/line.brand.json`

```json
{
  "preset": "emerald",
  "product": {
    "name": "My Project",
    "short_name": "MyProject",
    "app_id": "com.example.myproject",
    "publisher": "My Studio",
    "window_title": "My Project",
    "description": "Официальный лаунчер проекта"
  },
  "assets": {
    "logo": "assets/logo.svg",
    "app_icon": "assets/app-icon.svg"
  },
  "palette": {},
  "attribution": { "placement": "footer", "language": "ru" }
}
```

| Поле                   | На что влияет                                                                       |
| ---------------------- | ----------------------------------------------------------------------------------- |
| `preset`               | готовая палитра: `obsy` (по умолчанию), `emerald`, `violet`, `amber`, `rose`, `sky` |
| `product.name`         | шапка, «О программе», имя установщика                                               |
| `product.app_id`       | идентификатор приложения и **каталог данных игрока**                                |
| `product.window_title` | заголовок окна ОС                                                                   |
| `assets.logo`          | знак в интерфейсе; путь **относительно папки `branding/`**                          |
| `assets.app_icon`      | из него генерируются `.ico`, `.icns` и PNG                                          |
| `attribution`          | где показывать обязательное упоминание Line Launcher                                |

> **`app_id` меняйте один раз до первого релиза.** От него зависит папка с
> установленными сборками и настройками: смена идентификатора даст игрокам новый
> пустой каталог.

> **Логотип:** квадратный SVG без фона, поля ~10%. Если внутри используется
> `currentColor`, знак автоматически перекрашивается под палитру. В
> SVG-комментариях нельзя писать `--` (на этом падает генератор иконок).

Подробности и все правила — [BRANDING.md](BRANDING.md).

### 4.4. Версия

Держите одинаковое значение в трёх местах:

```
package.json               "version": "0.2.0"
src-tauri/Cargo.toml       version = "0.2.0"
src-tauri/tauri.conf.json  "version": "0.2.0"
```

После правки `Cargo.toml` выполните `cargo update -p line-launcher --manifest-path
src-tauri/Cargo.toml` (или просто соберите приложение) — обновится `Cargo.lock`.

### 4.5. Применить и проверить

```sh
npm run brand        # пересоздаст CSS, константы, оверлей Tauri и иконки
npm run check        # проверка типов TypeScript
npm run dev          # откроется интерфейс в браузере (без настольных функций)
npm run tauri dev    # настоящее окно приложения в режиме разработки
```

`npm run dev` и `npm run build` вызывают `npm run brand` сами, поэтому отдельно
его запускать нужно только чтобы посмотреть на результат заранее.

## Шаг 5. Что должен отдавать ваш сервер

Лаунчеру нужны две вещи: **`config.json`** по HTTPS и **ZIP-сборка** игры.

Минимальный `config.json` (полное описание — [PROVIDER.md](PROVIDER.md)):

```json
{
  "schema_version": 1,
  "min_launcher_version": "0.1.0",
  "required_features": ["custom-auth-v1", "zip-sha256-v1"],
  "provider": {
    "id": "myproject",
    "name": "My Project",
    "auth": {
      "login_url": "https://launch.example.com/api/login",
      "register_url": "https://launch.example.com/api/register"
    }
  },
  "servers": [
    {
      "id": "survival",
      "name": "Survival",
      "description": "Основной сервер",
      "version": "1.0.0",
      "distribution": {
        "url": "https://launch.example.com/packs/survival.zip",
        "sha256": "<64 hex-символа>",
        "size_bytes": 123456,
        "unpacked_size_bytes": 234567
      }
    }
  ]
}
```

Правила, на которых чаще всего спотыкаются:

1. `sha256` — хеш **самого ZIP-файла**, `size_bytes` — его размер в байтах,
   `unpacked_size_bytes` — сумма размеров файлов внутри. Лаунчер проверяет всё
   это и откажется ставить сборку при расхождении.
2. Чтобы работала кнопка «Играть», внутри ZIP нужен `line-launch.json`, а у
   сервера — **либо** пара `auth.launch_ticket_url` + `auth.session_exchange_url`,
   **либо** явный `"launch_mode": "offline"` без этих полей. Просто забытая
   авторизация не включает офлайн-режим.
3. Лаунчер **не скачивает произвольный Minecraft** и не содержит пиратских
   зеркал. Он автоматически скачивает ZIP, который вы разместили на своём
   HTTPS-сервере, проверяет SHA-256/размеры и запускает его. Клиент, библиотеки,
   ассеты и нативы должны быть в сборке; вы отвечаете за право её распространять.
   Как упаковать сборку — [GAME.md](GAME.md).

### 5.1. Офлайн-сборка вашего проекта

Для запуска с ником аккаунта проекта, без отдельного билета сервера и без
Microsoft-входа, добавьте серверу:

```json
{
  "launch_mode": "offline"
}
```

Поля `auth.launch_ticket_url` и `auth.session_exchange_url` у такого сервера
должны отсутствовать. В `required_features` конфигурации добавьте
`"offline-launch-v1"`, чтобы старый лаунчер не пытался угадать режим. Игрок всё
равно входит в аккаунт **вашего проекта**; его ник передаётся игре. Приватный
IPC-канал не создаётся, обмен ticket не ожидается. Проверка файлов, изоляция
каталога игры, выбор Java и кнопка остановки работают так же, как обычно.

Это режим для вашей локальной сборки, а не обход лицензии Minecraft и не
загрузчик чужих клиентов. Полная упаковка и ограничения — [GAME.md](GAME.md).

Посмотреть рабочий образец целиком можно в `examples/`:

```sh
npm run provider:pack     # соберёт тестовый ZIP и config.json в .provider/
npm run provider:serve    # поднимёт HTTPS на https://127.0.0.1:8443/config.json
npm run test:provider     # проверит контракт (нужен JDK)
```

## Шаг 6. Собрать установщик для игроков

```sh
npm run tauri:build
```

Команда сама: применит брендинг → **проверит, что `config_url` заполнен** →
прогонит doctor → соберёт Rust в release → сделает установщики. На Windows это
два прохода (NSIS и MSI), потому что установщики по-разному читают лицензию.
Аргументы `--features`, `--all-features` и `--debug` запрещены: дев-доверие к
локальному сертификату не должно попасть в распространяемый установщик.

**Где искать результат:**

| ОС      | Папка                                                       | Файлы                          |
| ------- | ----------------------------------------------------------- | ------------------------------ |
| Windows | `src-tauri/target/release/bundle/nsis/`                     | `*-setup.exe`                  |
| Windows | `src-tauri/target/release/bundle/msi/`                      | `*.msi`                        |
| macOS   | `src-tauri/target/release/bundle/dmg/`                      | `*.dmg`                        |
| Linux   | `src-tauri/target/release/bundle/deb/`, `appimage/`, `rpm/` | `*.deb`, `*.AppImage`, `*.rpm` |

Собирается только то, что поддерживает ваша ОС: `.msi` нельзя собрать на Linux,
`.dmg` — на Windows.

**Перед раздачей игрокам:**

- [ ] `branding/provider.json` содержит боевой адрес, а не `127.0.0.1`;
- [ ] `config.json` открывается браузером по HTTPS с доверенным сертификатом;
- [ ] `npm run brand:check` и `npm test` проходят;
- [ ] установщик поставлен на чистую машину и игрок вошёл без ввода ссылок;
- [ ] упоминание **Line Launcher | Plus In Plus** видно в интерфейсе (условие
      лицензии, убирать нельзя);
- [ ] сборка **не** содержит фичу `dev-provider-ca` — она только для демо и в
      `npm run tauri:build` не попадает;
- [ ] решён вопрос подписи кода (иначе Windows SmartScreen предупредит игроков) —
      [RUNBOOK.md](RUNBOOK.md), раздел 7.

## Частые ошибки

| Что видите                                      | Причина                                      | Что сделать                                                         |
| ----------------------------------------------- | -------------------------------------------- | ------------------------------------------------------------------- |
| `rustc: command not found` / «не найден в PATH» | терминал открыт до установки Rust            | закрыть и открыть терминал; если не помогло — переустановить rustup |
| `link.exe not found`, `MSVC не установлен`      | нет Build Tools                              | шаг 1.3, нагрузка «Разработка классических приложений на C++»       |
| `cargo metadata: program not found`             | то же, что и выше                            | поставить Rust и Build Tools, перезапустить терминал                |
| Окно не открывается на Windows                  | нет WebView2                                 | поставить Evergreen WebView2 Runtime                                |
| `Не найден openssl`                             | нет openssl                                  | Windows: поставить Git for Windows; Linux: `apt install openssl`    |
| `Порт 8443 уже занят`                           | другое приложение или прошлое демо           | `npm run demo -- --port 8553`                                       |
| «Сборка не настроена»                           | пустой `config_url`                          | заполнить `branding/provider.json`, пересобрать                     |
| Сборка установщика остановилась                 | тот же пустой адрес                          | это защита: игроку не должен достаться пустой лаунчер               |
| `TLS`/«сертификат не доверен» в демо            | провайдер запущен без демо-режима            | запускать приложение через `npm run demo` или `npm run demo:app`    |
| `JAVA_REQUIRED` при запуске                     | нет Java нужной версии                       | поставить JDK той версии, что объявлена в `line-launch.json`        |
| Кнопка «Играть» выключена в демо                | нет JDK или у сервера не настроены эндпоинты | шаг 1.4; сервер Demo Showcase сделан таким нарочно                  |
| `Found version mismatched Tauri packages`       | версии npm и Rust разошлись                  | `npm run check:tauri` покажет, что выровнять                        |
| Долго висит на `Compiling`                      | первая сборка Rust                           | подождать; дальше будет быстро                                      |

Полный список с подробными командами — [RUNBOOK.md](RUNBOOK.md).

## Шпаргалка команд

```sh
npm ci                    # поставить зависимости (один раз)
npm run doctor            # проверить окружение для приложения
npm run demo:doctor       # проверить окружение для демо
npm run demo              # демо: провайдер + окно приложения
npm run demo:app          # подключить окно к уже запущенному демо-провайдеру
npm run demo:update       # выпустить обновление в демо (проверка update/rollback)
npm run dev               # интерфейс в браузере (без настольных функций)
npm run tauri dev         # окно приложения в режиме разработки
npm run brand             # применить брендинг и иконки
npm run brand:check       # убедиться, что генерируемые файлы актуальны
npm run check             # проверка типов
npm test                  # тесты интерфейса и контрактов
npm run test:rust         # тесты чистой Rust-логики
npm run tauri:build       # установщики для игроков
```
