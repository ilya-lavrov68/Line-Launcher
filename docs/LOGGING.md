# Логи и диагностика

Что лаунчер пишет на диск, где это лежит и что уходит в поддержку. Без этого
раздела первый же отчёт «не работает вход» невозможно превратить в ответ:
именно так и случилось в первом раунде демо.

## Где лежит

```
<app-data>/
├── instances/<id>/          сборки игрока (как было)
├── minecraft/<id>/game/logs/launch.log  ← вывод текущего запуска Minecraft
├── minecraft/<id>/logs/launch.log       ← журнал старого способа запуска, если есть
├── launcher_logs/           ← логи самого лаунчера
│   ├── launcher-2026-11-13.log   сегодня
│   ├── launcher-2026-11-12.log
│   └── … файлы за последние 30 дней
├── config-cache.json
├── settings.json
└── skins/
```

`<app-data>` на каждой системе:

| Система | Путь                                                             |
| ------- | ---------------------------------------------------------------- |
| Windows | `%APPDATA%\studio.plusinplus.line-launcher\`                     |
| Linux   | `~/.local/share/studio.plusinplus.line-launcher/`                |
| macOS   | `~/Library/Application Support/studio.plusinplus.line-launcher/` |

Папку не нужно искать: **Настройки → Логи и поддержка → «Открыть папку с
логами»** открывает её в файловом менеджере.

### Отдельно — лаунчер и Minecraft

`minecraft/<id>/logs/launch.log` — stdout/stderr последнего запуска игры для
экземпляра. `launcher_logs/` — действия самого лаунчера. Это отдельные журналы,
но «Скопировать диагностику» теперь включает оба типа: все суточные журналы
лаунчера за 30 дней и `launch.log` каждого экземпляра в `game/logs/` и (для
старых сборок) в `logs/`. Перед копированием
игровые строки с признаками токенов, паролей или авторизации скрываются; обычные
строки также проходят `scrub`. Пути, не являющиеся обычными файлами/каталогами
(симлинки и Windows reparse points), не читаются.

## Формат

Одна запись — одна строка, `ключ=значение`:

```
2026-11-13T11:20:03.412Z ERROR auth     login failed user=Player_1 stage=provider code=INTERNAL retryable=false msg=API провайдера не соответствует контракту авторизации.
2026-11-13T11:20:03.660Z INFO  auth     login ok user=Player_1
```

| Поле      | Значение                                                               |
| --------- | ---------------------------------------------------------------------- |
| время     | RFC 3339, UTC, миллисекунды                                            |
| уровень   | `DEBUG` · `INFO` · `WARN` · `ERROR`                                    |
| область   | `app` · `config` · `auth` · `install` · `launch` · `skin` · `settings` |
| сообщение | фиксированная фраза лаунчера, не текст ответа провайдера               |
| поля      | `key=value`, разделены пробелом                                        |

Почему не JSONL: файл читает человек. Строка должна быть понятна без
инструментов и копироваться в переписку как есть. При этом она остаётся
машиночитаемой — `grep`, `awk`, любой парсер по пробелам.

## Что пишется и что нет

| Пишется                              | Не пишется никогда                 |
| ------------------------------------ | ---------------------------------- |
| версия, ОС, архитектура              | пароль                             |
| провайдер, адрес конфига             | `access_token`, `session_secret`   |
| состояние сессии (имя игрока)        | launch ticket                      |
| этап и код ошибки, `retryable`       | тело запроса или ответа провайдера |
| размеры, длительности, sha256 релиза | содержимое сборок, миров, скинов   |

Секрет не может попасть в строку случайно: значение пишется через тип
`Field`, единственный конструктор которого — `Field::text` — прогоняет текст
через `scrub`. Тот заменяет всё, что похоже на учётные данные (`Bearer …`,
`token=…`, `password=…`), а переводы строк вырезает, чтобы значение не могло
подделать целую запись.

Это требование `RUNBOOK.md` («логи не должны содержать ticket, пароль или
access-токен»), и теперь оно подкреплено типом, а не дисциплиной.

## Ротация

- один файл в сутки, имя `launcher-YYYY-MM-DD.log`;
- журналы лаунчера хранятся **30 дней**, без ограничения количества файлов;
  старые удаляются по времени изменения при запуске лаунчера и после записи;
- удаляются только обычные файлы, чьё имя точно совпадает с шаблоном:
  чужие файлы в папке не трогаются;
- одна запись по-прежнему ограничена 8 КиБ, чтобы одна патологическая ошибка
  не раздувала строку бесконечно.

## Три кнопки в настройках

Раздел **Настройки → Логи и поддержка**.

| Кнопка                      | Что делает                                       |
| --------------------------- | ------------------------------------------------ |
| **Открыть папку с логами**  | показывает `launcher_logs/` в файловом менеджере |
| **Скопировать диагностику** | кладёт в буфер готовый отчёт (см. ниже)          |
| **Отправить в …**           | черновик письма издателю сборки                  |
| **Связаться с провайдером** | черновик письма провайдеру, если он указал адрес |

Оба письма содержат **тот же** отчёт, что копирует вторая кнопка. Провайдер и
издатель не могут получить разные версии одного сбоя.

### Два адреса и почему они разные

| Кому            | Откуда берётся                           | Кто может изменить                |
| --------------- | ---------------------------------------- | --------------------------------- |
| Издатель сборки | `branding/owner.ts`                      | только тот, у кого есть исходники |
| Провайдер       | `config.json` → `provider.support_email` | провайдер                         |

Адрес издателя **намеренно вынесен из конфига брендинга**: провайдер
перекрашивает сборку под себя через `branding/line.brand.json` и
`branding/provider.json`, и если бы почта лежала там, перекрасивший сборку мог
бы перенаправить себе диагностику всех игроков. Ключ `owner` (или `support`) в
бренд-конфиге — ошибка сборки, а не тихо принятое значение.

Пустой адрес издателя — это не ошибка, а честное состояние: кнопки письма
просто нет, «Скопировать диагностику» остаётся.

### Формат письма

`mailto:` собирается лаунчером, а не приходит из конфига. Поэтому в поле
адреса не может попасть схема, запрос или путь: адрес проверяется дважды — при
сборке (`validateSupportEmail`) и в Rust при разборе конфига
(`valid_support_email`). Тело кодируется процентно, так что перевод строки не
ломает ссылку.

## Отчёт диагностики

```
Line Launcher — диагностика
Отправляется в поддержку проекта. Пароля и токенов здесь нет.

[окружение]
version=0.10.0
os=windows arch=x86_64
utc=2026-11-13T11:25:01Z
data_dir=C:\Users\…\AppData\Roaming\studio.plusinplus.line-launcher
launcher_logs=C:\Users\…\AppData\Roaming\studio.plusinplus.line-launcher\launcher_logs

[провайдер]
provider_id=line-demo
config_url=https://127.0.0.1:8443/config.json
session=signed_out

[сборки]
instance=demo

[логи: launcher за последние 30 дней; игровые launch.log]
--- launcher log: launcher-2026-11-13.log ---
…
--- Minecraft launch.log, instance=demo ---
…
```

Отчёт содержит все строки журналов лаунчера за retention-период и текущие
`launch.log` сборок, без лимита на количество строк. Перед копированием игровые
строки с возможными секретами целиком скрываются. Если полный отчёт слишком
велик для `mailto:`, черновик откроется с подсказкой: скопируйте диагностику и
вставьте её вручную либо приложите файлы.

## Как это отвечает на «лаунчер не пускает»

До появления логов единственным следом сбоя входа был красный текст на экране.
Теперь в `launcher-…log` появляется:

```
ERROR auth login failed user=Player_1 stage=provider code=INTERNAL retryable=false msg=…
```

и `stage` сразу делит проблему на три разные:

| `stage`    | Где смотреть                                                         |
| ---------- | -------------------------------------------------------------------- |
| `input`    | проверка логина/пароля в самом лаунчере                              |
| `provider` | сеть, TLS, HTTP-статус, адрес провайдера                             |
| `response` | ответ провайдера не по контракту (формат `config.json`, тела логина) |
| `store`    | состояние лаунчера занято (идёт установка или игра)                  |
| `session`  | сессия истекла или её нет                                            |
