# Installation and false-positive remediation roadmap

## Scope and current behaviour

Providers can supply a pinned ZIP or a Modrinth/packwiz source. The installer verifies the ZIP's published digest, indexes extracted files, and verifies source files against their supplied hashes. A local index records what was installed; it does not authenticate a malicious or compromised provider. CurseForge source resolution is **not implemented**: its API and distribution restrictions must be resolved before support is promised.

A Prism instance is not necessarily a complete standalone Minecraft directory: it normally describes components in `mmc-pack.json` and may rely on Prism's shared versions, assets and libraries. The current ZIP inspector reads Mojang version profiles, not Prism component metadata. For a Prism-shaped ZIP without those profiles, it now stops with a clear diagnostic even if the server provides a vanilla hint, rather than silently treating the hint as the installed loader. This is a guard, not Prism support.

## Implementation phases

1. **Plan before downloading:** parse and validate Prism component metadata from the verified ZIP, preserve explicit versions, reject ambiguous or unsupported components, and inventory the actual files needed by that profile (including platform-specific libraries and asset objects). A directory's existence alone is not proof of completeness. Do not execute Java paths or arbitrary commands from `instance.cfg` or pack metadata. Provide a typed, revision-bound preparation plan with missing components, sizes where known, and download sources.
2. **Consent and repair:** show that plan before fetching missing ZIP components; refuse means no component download or installation. On acceptance, revalidate the revision and plan, fetch only missing or invalid files from approved sources, verify expected hashes where available, stage and atomically commit, reuse intact assets and existing loader installations. Do not rerun an installed loader merely because another file is missing. Java is detected separately and a separate installation is offered if necessary. Define an explicit failure when a component cannot be safely verified or repaired.
3. **Source packs:** preserve hash-verified Modrinth/packwiz reuse and the provider's intended version. Research supported CurseForge API credentials, rate limits and third-party distribution restrictions; report unavailable files rather than inventing bypasses. User confirmation policy for source packs must be explicit and distinct from ZIP repair.
4. **Runtime artifacts and false positives:** distinguish verified provider files, personal data and generated caches. Connector's 1.20.1 `.connector/temp` can contain nested jars extracted from verified input; transformed output is executable and cannot be trusted just because of its path or a first-run snapshot. Design provenance and validation or safe regeneration for each artifact class, without deleting personal files or allowing a cache directory to bypass checks. Inspect actual Connector versions and loader discovery rules, including symbolic links and Windows reparse points.
5. **Windows validation:** use representative Prism exports (vanilla, Fabric, Forge, NeoForge), incomplete and complete ZIPs, Modrinth and permitted CurseForge fixtures. Exercise first install, offline/repeat, updates, tampering, corrupted or missing files, consent refusal, interruption/recovery and Connector-generated cache. Record timings and network activity; confirm no accidental reinstallation and preserve worlds/settings.

No phase should treat all files observed after a first game launch as trusted; a crash, unrelated process or malicious file could contaminate that snapshot. Unknown generated artifacts require a clear actionable message, not a silent allowance or deletion.
