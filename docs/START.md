# Быстрый старт Line Launcher

Короткая инструкция. Если собираете впервые и не знаете, с чего начать —
[BUILD.md](BUILD.md): установка программ, какие файлы менять, сборка установщика.
Подробности — в [RUNBOOK.md](RUNBOOK.md), контракт API — в
[PROVIDER.md](PROVIDER.md), брендинг — в [BRANDING.md](BRANDING.md).

Хотите сначала посмотреть, как всё работает? `npm run demo` поднимет локальный
демо-провайдер и откроет настоящее приложение — [DEMO.md](DEMO.md). Как лаунчер
запускает сборку и защищает её файлы — [GAME.md](GAME.md).

## Я игрок

1. Установите лаунчер, который вам дал ваш игровой проект.
2. Откройте его. Список серверов загрузится сам — адрес вводить не нужно.
3. **Регистрация** или **Вход** — один раз на весь проект.
4. Выберите любой сервер → **Установить сборку** → **Играть**. На остальных
   серверах вход повторять не нужно.

Каталог показывает последний открытый сервер отдельно, а остальные серверы —
единым компактным списком. Используйте поиск и фильтры, чтобы быстро найти
нужную сборку; личные секции и порядок серверов сохраняются между запусками.

В настройках **Рабочая зона** по умолчанию выбрана сплошная отделка главных
панелей — тёмно-серая, как в JetBrains IDE. Анимированный фон при этом остаётся
на месте; вариант «Прозрачные панели» показывает его и сквозь панели.

Выйти из аккаунта можно кнопкой рядом с логином в меню слева — это закрывает
доступ сразу ко всем серверам проекта. Если сессия истекла, лаунчер сам вернёт
вас на этот экран — просто войдите заново.

В **Профиле** широкий 3D-просмотр активного скина становится главным визуальным
элементом, а данные аккаунта и действия остаются собранными в компактной строке.
Ходьба включена по умолчанию; приветствие и ручное вращение можно выбрать
отдельно. Свёрнутая панель статистики пока показывает пустое состояние: серверный
API ещё не согласован и не подключён, поэтому примерных счётчиков нет.

Если список не загрузился — проверьте интернет и нажмите **Повторить**. Если
автоматический поиск Java не нашёл подходящий рантайм, в настройках можно
повторить поиск или указать путь к `java.exe`/папке JDK вручную — лаунчер
проверит его сам.

**Гардероб** открывается после входа в аккаунт проекта. Добавьте PNG 64×64 или
64×32 — он сохранится в локальной истории на этом компьютере. Активный скин один
на аккаунт и **отправляется на сервер сам** — при выборе, входе и открытии
гардероба. Отдельной кнопки нет: внизу видно статус («отправляем», «отправлен»,
«не удалось — повторим»).

## Я провайдер: собрать лаунчер под свой проект

Нужны **Node.js 22+**, **Rust stable** и
[зависимости Tauri v2](https://tauri.app/start/prerequisites/).

```sh
npm ci
npm run doctor          # проверит окружение и подскажет, чего не хватает
```

### Шаг 1. Свой адрес

Один лаунчер = один провайдер. Ваши серверы перечисляются не здесь, а в
`config.json`, который отдаёт этот адрес.

`branding/provider.json`:

```json
{
  "config_url": "https://ваш-домен/line/config.json"
}
```

Только `https://`, без логина/пароля в ссылке и без `#`. Пустое значение — это
ненастроенный шаблон: в режиме разработки появится поле ссылки, а сборка
установщика будет остановлена с понятной ошибкой.

### Шаг 2. Свой вид

`branding/line.brand.json` — название, логотип и иконка.

```json
{
  "product": { "name": "My Project" },
  "assets": { "logo": "assets/logo.svg" }
}
```

Цвета интерфейса фиксированы: палитра подобрана под раскладку и контраст, и
брендинг её не меняет. Ключи `preset`/`palette` из версий до 0.12.0 больше не
принимаются — сборка остановится с объяснением.

### Шаг 3. Сборка

```sh
npm run tauri:build
```

Команда сама применит брендинг, проверит что адрес заполнен и соберёт
установщики (на Windows — NSIS и MSI). Результат в `src-tauri/target/release/bundle/`.

Готово. Игроку остаётся один раз зарегистрироваться или войти — дальше доступны
все серверы из вашего конфига.

> Упоминание **Line Launcher | Plus In Plus** в интерфейсе — условие лицензии.
> Его нельзя убирать. Место и язык выбираются в `branding/line.brand.json`.

### Что должен отдавать ваш сервер

Минимум: `config.json` со списком серверов и эндпоинты входа/регистрации в
`provider.auth` — аккаунт один на проект, поэтому они не зависят от сервера.
Гардероб (`provider.wardrobe`) тоже общий; эндпоинты запуска (`server.auth`)
остаются отдельными для каждого сервера.
Полное описание полей, ограничения и примеры — [PROVIDER.md](PROVIDER.md).
Готовый образец конфига — [examples/config.json](../examples/config.json).

Проверить связку без Minecraft:

```sh
npm run provider:pack     # тестовая сборка + config.json
npm run provider:serve    # https://127.0.0.1:8443/config.json
npm run test:provider
```

## Я разработчик лаунчера

```sh
npm ci
npm run dev               # только интерфейс, без desktop-оболочки
npm run tauri dev         # полное приложение
```

Пока `branding/provider.json` пуст, `npm run dev` показывает поле ссылки — это
удобство для разработки, в готовой сборке его нет.

### Проверки

```sh
npm test                  # контракт, брендинг, лицензия, логика игрока
npm run check             # TypeScript
npm run build             # production-сборка интерфейса
npm run brand:check       # сгенерированный брендинг актуален
npm run test:rust         # чистая Rust-логика без crates.io
npm run test:wardrobe     # скин-эндпоинты по HTTPS
npm run demo:check        # демо-проект целиком по HTTPS, без JDK и Rust
```

Браузерные проверки (нужен запущенный `npm run dev` в другом терминале):

```sh
npm run test:ui           # сквозной сценарий интерфейса
npm run test:boot         # подключение при старте ровно один раз
npm run screenshots       # обновить картинки для README (1280x800)
npm run screenshots:offline  # приблизительные рисунки в .offline-shots/, не снимки
```

Скачивать браузер не нужно: `scripts/lib/find-browser.mjs` берёт уже
установленный Chrome, Edge или Chromium (на Windows первым делом Edge — он есть
везде). Если браузер лежит не там, укажите путь явно:

```sh
CHROMIUM_PATH=/path/to/chrome npm run screenshots
```

`npx playwright-core install chromium` для этого не требуется и в средах без
доступа к CDN Playwright просто не сработает.

При изменении интерфейса, установки или поведения обновляйте связанные разделы
README и `docs/` в том же PR. Исторические планы и результаты не являются
подтверждением текущей ветки: текущие ограничения — в
[INSTALLATION-AUDIT.md](INSTALLATION-AUDIT.md) и [VERIFICATION.md](VERIFICATION.md).
Скриншоты обновляются только после успешного полного браузерного прохода; данные
и команды Tauri при съёмке заменены тестовой заглушкой.

Rust целиком:

```sh
cargo fmt --manifest-path src-tauri/Cargo.toml --check
cargo test --locked --manifest-path src-tauri/Cargo.toml
cargo clippy --locked --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
```

`npm audit` ругается на инструменты сборки — они не попадают в бандл. Проверять
нужно `npm audit --omit=dev`.

Что проверено, а что нет — [VERIFICATION.md](VERIFICATION.md).

## Частые проблемы

| Симптом                                         | Что делать                                                                                                                   |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `cargo metadata: program not found`             | Не установлен Rust. `npm run doctor` покажет, чего не хватает                                                                |
| Список серверов не грузится                     | Проверьте интернет, нажмите **Повторить**. Адрес зашит в сборку — менять его игроку не нужно                                 |
| Скин не появился на сервере                     | Гардероб покажет причину под «Скин на серверах проекта». Отправка повторится сама при следующем входе или открытии гардероба |
| «Сборка не настроена»                           | Тот, кто собрал лаунчер, не заполнил `branding/provider.json`                                                                |
| Сборка установщика остановилась на `config_url` | Заполните `branding/provider.json` и повторите                                                                               |
| `tauri dev` не находит WebView2 (Windows)       | Установите WebView2 Runtime; подробности в [RUNBOOK.md](RUNBOOK.md)                                                          |
| Нужен пропуск проверки окружения                | `LINE_SKIP_DOCTOR=1 npm run tauri dev`                                                                                       |

Полный разбор проблем и ручные проверки — [RUNBOOK.md](RUNBOOK.md).
