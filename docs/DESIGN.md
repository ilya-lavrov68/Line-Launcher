# Дизайн-система Line

Как устроено оформление лаунчера, откуда взяты токены и что делать, когда
хочется «как в плеере». Читать перед любой правкой UI.

Две темы, один код:

| `data-theme` | Что это                                   | Где живёт                     |
| ------------ | ----------------------------------------- | ----------------------------- |
| `line`       | текущий дизайн (по умолчанию)             | `src/styles/themes.css`       |
| `old`        | предыдущий дизайн, сохранён без изменений | `src/index.css` (легаси-блок) |

Переключение — одна кнопка в сайдбаре и в «Настройки → Оформление». Выбор
хранится в `localStorage` (`line.theme`) и применяется до первого кадра
(`bootstrapTheme()` в `src/index.tsx`), поэтому вспышки чужой палитры нет.

## Что взято из tryliner и что изменено

Источник: `tryliner/desktop` — музыкальный плеер на Electron с FSD, Tailwind v4
и стеклянными поверхностями. Перенесены **принципы и токены**, не экраны.

| tryliner                                                             | Line                                                                    | Почему изменено                                                                                  |
| -------------------------------------------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `--fill-subtle / fill / fill-hover / fill-strong`                    | те же четыре ступени в `themes.css`                                     | универсальная шкала «тихих заливок», не привязана к музыке                                       |
| `--surface-glass` + `backdrop-blur-2xl backdrop-saturate-150`        | `--surface-glass` + `blur(20px) saturate(140%)`, `[data-line-glass]`    | меньше развлекательного свечения: размытие мягче, сатурация ниже, одна тень вместо «парения»     |
| `rounded-control / item / panel` (8 / 12 / 20)                       | `--radius-control / item / panel` (8 / 12 / 18)                         | 18px вместо 20px — панель не выглядит «таблеткой» на 1024px                                      |
| `text-caption / body / label / title / heading`                      | те же размеры, но через явные `[Npx]` в компонентах                     | в проекте нет шкалы в `@theme`, дублировать её ради двух компонентов нерационально               |
| `ease: [0.22, 1, 0.36, 1]`, 0.12–0.22s, spring 260–320/damping 20–22 | те же числа                                                             | движение — самая переносимая часть; пользователь узнаёт «тот самый» отклик                       |
| Cover art задаёт цвет всего экрана                                   | один фиксированный градиент `--line-canvas` с акцентом бренда           | у лаунчера нет обложки, которую можно усреднить; случайный скриншот не должен менять цвет кнопок |
| Now Playing bar: обложка, транспорт, seek, volume                    | `ServerActionPanel`: имя сервера, статус, прогресс сборки, одна кнопка  | см. ниже                                                                                         |
| Library / Album art карточки                                         | `ServerCard` (существующий) — стекло, логотип, версия, статус установки | структура уже была правильной; меняются токены, не сетка                                         |
| Fullscreen player, lyrics canvas, equalizer, visual modes            | **удалено**                                                             | в лаунчере нет ни музыки, ни времени, которое надо визуализировать                               |

## Токены

Всё, что читают компоненты, объявлено в `src/styles/themes.css`.

- **Цвет.** Новый дизайн **переопределяет те же слоты**, что и старый
  (`--background`, `--card`, `--border`, `--primary`, …). Поэтому существующие
  компоненты перекрашиваются сами, а `data-theme="old"` возвращает значения из
  `index.css` без копирования.
- **Заливки.** `bg-fill-subtle` < `bg-fill` < `bg-fill-hover` < `bg-fill-strong`.
  Для всего, что лежит _внутри_ стекла: поля, строки, чипы, вторичные кнопки.
- **Стекло.** `[data-line-glass]` (панель) и `[data-line-glass="dock"]` (док
  действия). Стекло не вкладывается в стекло: внутренние блоки — `bg-fill`.
- **Радиусы.** `--radius-control` (кнопки, чипы), `--radius-item` (строки,
  карточки, док), `--radius-panel` (диалоги, верхнеуровневые контейнеры).
- **Статусы.** `--line-online`, `--line-update`, `--line-offline`, `--line-error`.
  Зелёный/янтарный/серый/красный — единственные «смысловые» цвета.
- **Движение.** `--ease-line` (0.22, 1, 0.36, 1), `--dur-fast` 120ms,
  `--dur-page` 220ms. Пружины — только для того, что «приземляется»
  (кнопка, карточка), не для фонов.

Правила, которые легко нарушить:

1. Не писать hex в компоненте — только слот или `color-mix` от него.
2. Не ставить `backdrop-blur` на вложенный блок внутри `[data-line-glass]`.
3. Не анимировать фон на новом дизайне: постоянный градиент статичен (у старого
   остаётся `gradientBg`, и это часть его вида).
4. Любая новая поверхность должна иметь деградацию под
   `[data-theme="old"] [data-line-glass]`, иначе старый дизайн получит пустую
   коробку.

## Как работает переключение

```
index.html            data-theme="line"   ← значение по умолчанию до JS
src/index.tsx         bootstrapTheme()    ← читает localStorage, ставит атрибут
ThemeProvider         applyTheme/writeTheme при клике
themes.css            :root:not([data-theme="old"]) { новые слоты }
                      [data-theme="old"] { только доп. токены }
```

Структурная разница (две разные вёрстки детали сервера) живёт в
`ServerDetail.tsx` как две ветки по `useTheme()`. Это осознанно: два дерева в
DOM под `hidden` дали бы скринридеру и smoke-тесту по две кнопки «Играть».
Цветовая разница — всегда CSS.
