# UI-аудит: завершённый снимок и ограничения проверки

## Область проверки

Проверены исходники экранов `src/components/line` и общего компонента Button: состояния кнопок, появление прогресса и ошибок, обновление каталога, переходы, вход, история, настройки и гардероб. Это аудит реализации и автоматизированных сценариев, а не доказательство отсутствия всех ошибок во всех сочетаниях окон, языков и состояния данных.

## Найдено и исправлено

- Детали сервера: панель была прижата к низу через `mt-auto`, поэтому добавление прогресса увеличивало её и сдвигало панель вверх. Теперь панель остаётся в потоке, а прогресс появляется после основных действий. Это применяется и к обычным серверам, и к Minecraft.
- Minecraft: активная подготовка отслеживалась только внутри панели. Переход на другой экран мог размонтировать её, скрыть состояние операции и дать запустить повторное действие. Панель сохраняется смонтированной при переходе на другой экран, а текущая операция показывается в компактном виджете; переподключение и повторные действия блокируются, двойной вызов защищён синхронным флагом. Состояние не сбрасывается раньше завершения команды при событии `starting`.
- Состояние Minecraft больше не говорит «Готов к запуску» во время подготовки.
- Общая кнопка сдвигалась на пиксель при нажатии, основное действие дополнительно масштабировалось. Эти движения убраны.
- При обновлении каталога исчезала кнопка добавления секции, а ширина кнопки обновления менялась. Кнопка добавления остаётся на месте, но недоступна на время обновления; ширина текста зарезервирована. Та же стабилизация применена к проверке ресурс-паков, поиску Java, сохранению скина и полю подключения. Кнопки отката больше не сжимаются до значка во время работы.
- Обновление конфигурации не должно выталкивать с открытой страницы сервера, если сервер всё ещё существует; его данные заменяются, экран и квитанция сохраняются. Если сервер удалён или сеанс исчез, выполняется выход с этой страницы.
- Dev-шаблон без подключённого провайдера раньше перекрывал форму адреса недоступной страницей входа. Форма доступна до получения конфигурации; навигация без сессии закрыта.
- Исправлен устаревший UI smoke: после добавления раздела поддержки в настройках он ожидал шесть значков вместо семи.
- Для ровных отступов основная панель использует одинаковые адаптивные поля `p-4 → p-5 → p-6`, а содержимое настроек ограничено `max-w-4xl` и центрируется. Секции настроек сделаны плоскими и разделены тонкими линиями. Обводка убрана только у плашки активной категории настроек; состояние выбранной рабочей области не менялось.
- Каталог серверов сохраняет текущую очередность действий, но последняя выбранная серверная витрина с реальным баннером/описанием получает больше визуального веса и места; поиск, фильтры и сетка следуют ниже без придумывания содержимого.
- Профиль перекомпонован в минималистичный hero: широкая 3D-сцена занимает верх страницы, имя скина ненавязчиво подписано поверх сцены, позы и статус синхронизации идут в плоской полосе ниже, а сведения аккаунта и действия собраны в компактный ряд. Статистика остаётся отдельным раскрываемым блоком; skeleton повторяет композицию.
- В профиле переключатель позы получил мягкую анимированную плашку вместо выделения тенью; фон 3D-просмотра стал более атмосферным без карточной тени, а непонятный символ раскрытия статистики заменён на стандартный Chevron. Категории настроек остаются вертикальной навигацией слева на широком экране, с плавно перемещающейся по вертикали активной плашкой; только на узком экране навигация становится горизонтальной для удобства. Это обычная часть раскладки, не всплывающее меню; движение отключается при `prefers-reduced-motion`. Обновлённый экран настроек захвачен в реальном браузере, а UI smoke проверяет переключение и локализованные подписи.
- Радиусы кнопок, активных переключателей и элементов segmented navigation приведены к `rounded-lg`, как у navbar; малые размеры общего Button и Select больше не получают отдельные угловатые варианты. Контейнер общего Switch также использует `rounded-lg`.
- Для стыкующихся кнопок дока и игрового меню сведены перекрытия радиусов: радиус внутреннего контура уменьшается на 1 px относительно внешнего. Формула вложенных контуров записана в `.agents/skills/product-design/SKILL.md` и `docs/DESIGN.md`: `innerRadius = max(0, outerRadius - insetDistance)`; у рамки с padding расстояние включает толщину рамки и padding.
- Навигация настроек получила колонку 224 px, чтобы длинные локализованные категории не обрезались. UI smoke теперь отдельно проверяет ширину текста каждого ярлыка на четырёх языках. Нижняя группа боковой панели выровнена по полям верхней группы.

## Проверки

- `npm run test:dock`: браузер Chromium, заглушка backend, ширины 1100 и 640 px; координаты основных кнопок до и во время прогресса, после ошибки, нажатия тестового режима и подготовки, блокировка/разблокировка навигации, обычный сервер, стабильность кнопки обновления и добавления секции.
- `npm run test:drag`: браузерная проверка перетаскивания карточек с заглушкой.
- `npm run test:ui`: браузерный smoke с заглушкой Tauri: подключение и вход, каталог, настройки, гардероб и прочие сценарии (149 вызовов IPC, без ошибок страницы на момент проверки).
- TypeScript, npm-тесты и production-сборка см. результат текущего запуска в ответе на PR.

## Ограничения этого исторического прогона

Перечисленные выше измерения и браузерные сценарии — исторический результат
конкретного прогона, не текущий тестовый отчёт. Они использовали Chromium и
заглушки, не Windows WebView, реального провайдера или полноценную установку
Minecraft. Старые счётчики IPC и результат проверки не переносить на текущую
ветку без повторного запуска.

Текущее подтверждённое состояние — [VERIFICATION.md](VERIFICATION.md). Все
незавершённые UI и desktop-проверки учтены в едином
[ROADMAP.md](ROADMAP.md); этот аудит не является вторым списком задач.

## Текущий проход — 2026-11-17

На этой ветке повторно проверены основной путь от первого запуска до входа,
каталог, сервер и его меню действий, загрузка/ошибка, режим Minecraft, аккаунт,
гардероб, настройки и локализованные настройки. `npm run test:ui` пройден на
1280×900 и на минимальном размере окна 800×560: по 180 вызовов тестового IPC,
0 ошибок страницы; в сценарии проверяются прямой выбор каждой темы справочника,
отложенное закрытие, повторное открытие, Escape, горизонтальное переполнение и отсутствие обрезанных ярлыков категорий на четырёх языках.
Точечные проверки действий дока пройдены на 1100 и 640 px, перетаскивания и
полосы каталога — на 1280, 720 и 375 px. `npm run screenshots` записал 14
экранов и шесть GIF с шестью статичными постерами из реального браузера.

Системные исправления этого прохода: справочник стал напрямую навигируемой
справочной поверхностью с поддержкой Escape/focus trap, ручным воспроизведением
анимаций и доступом после отложения; короткая высота 800×560 получила
адаптивное окно и компактную навигацию без принудительной последовательности.
Зарезервированная область сообщений входа увеличена так, чтобы длинная ошибка
не сдвигала основное действие. Устаревший тест дока теперь ищет действующие
элементы меню, а не прежнюю отдельную кнопку.

Осталось проверить на целевой Windows/Tauri-сборке нативное окно, WebView2,
реальные серверные ответы и запуск игры; эти блокеры среды не проверяются
браузерной заглушкой и перечислены в [ROADMAP.md](ROADMAP.md). Неблокирующая
визуальная возможность: GIF показывают весь экран приложения, поэтому детали
внутри демонстрации на маленьком окне мелкие; инструкция остаётся основной, а
при необходимости кадры можно позднее заменить на более крупные предметные
фрагменты. Это улучшение не блокирует текущий сценарий справочника.
