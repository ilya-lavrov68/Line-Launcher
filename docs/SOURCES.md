# Источники сборок: packwiz и Modrinth (в разработке)

**Ещё не выпуск:** до применения конфигурации выполните Rust-проверки и
проверьте настоящий запуск. В текущей реализации источники работают только с
`launch_mode: "minecraft"` и требуют `server_address` и `minecraft_version`.
Этот режим использует офлайн-идентификатор Minecraft, а не ticket/session-exchange.

Укажите ровно один источник: либо `distribution`, либо `source`. Для `source`
не задавайте `distribution` и `pack_manifest_url`. В общей конфигурации добавьте
соответствующий элемент в `required_features`, чтобы старый лаунчер не пытался
открыть неподдерживаемый сервер. Остальные обязательные поля провайдера и
конфигурации остаются прежними.

Пример **одного сервера**, не полного `config.json`:

```json
{
  "id": "survival",
  "name": "Survival",
  "description": "Сборка проекта",
  "version": "1.0.0",
  "minecraft_version": "1.21.1",
  "launch_mode": "minecraft",
  "server_address": "play.example.org",
  "source": {
    "kind": "packwiz",
    "pack_toml_url": "https://raw.githubusercontent.com/OWNER/REPO/main/pack.toml"
  }
}
```

Для этого примера в корне конфига укажите `"required_features": ["packwiz-v1"]`.
URL должен указывать на содержимое raw `pack.toml`, а не на HTML-страницу GitHub;
все ссылки на файлы должны быть доступны по HTTPS. Поддерживаются только хеши
SHA-256 и SHA-512; записи с `metadata:curseforge` отклоняются. Проверяются хеши
индекса, метафайлов и скачанных файлов. Необязательные и серверные метафайлы
пропускаются.

Для Modrinth замените `source` и укажите `"required_features": ["modrinth-v1"]`:

```json
"source": {
  "kind": "modrinth",
  "project": "https://modrinth.com/modpack/PROJECT",
  "version": "VERSION_ID"
}
```

`project` также принимает slug или ID; `version` можно опустить для последнего
release. Вместо поля `version` можно указать URL конкретной версии
`https://modrinth.com/modpack/PROJECT/version/VERSION_ID`. Не указывайте версию
дважды. `.mrpack` и его файлы проверяются по SHA-512; общие и клиентские
`overrides` включаются, серверные не устанавливаются. Распакованные overrides
ограничены 128 МиБ. Файлы, доступные только через CurseForge, не поддерживаются.

## Конвертер packwiz

```sh
node scripts/pack-from-packwiz.mjs https://raw.githubusercontent.com/OWNER/REPO/main/pack.toml -o pack.zip
```

Для проверки без записи файла добавьте `--dry-run`: файлы всё равно скачиваются
и проверяются. Локальный путь до `pack.toml` также принимается, но внешние загрузки из локального источника не поддерживаются.
`pack.zip` содержит `install/` и внутренний `pack.json` со списком файлов; он
**не является** внешним `pack_manifest_url`, который ожидает URL архива, его
хеш и размеры. Для распространения как обычного ZIP настройте `distribution`
и протестируйте конкретную сборку в режиме Minecraft. Конвертер и клиент должны
совпадать по набору содержимого, но пока это не подтверждено сквозным тестом на
настоящем публичном паке.

## Что проверить перед распространением

Запустите Rust-тесты и установите оба типа сборки на чистый профиль. Сравните
пути и хеши игровых файлов с архивом конвертера; отдельно проверьте загрузчик,
overrides, отмену и повторную установку, повреждение файла и блокировку на
подозрительном ресурс-паке. Не публикуйте версию как готовую при ошибке любого
из этих шагов. Текущая кнопка проверки ресурс-паков и ручная диагностика не
заменяют проверки запуска на целевой ОС.

## Пример ссылки BattleArmory

Для переданной ссылки скачивания `cdn.modrinth.com/data/rQiXwLhB/versions/TQIsQXtg/...`
укажите идентификаторы проекта и версии, а не прямой URL архива:

```json
"source": {
  "kind": "modrinth",
  "project": "rQiXwLhB",
  "version": "TQIsQXtg"
}
```

В корне конфигурации нужен `"required_features": ["modrinth-v1"]`;
это фрагмент, не готовый конфиг. Версию Minecraft и загрузчик следует сверить
с индексом самого пакета. Параметры ссылки указывают на Minecraft 1.20.1 и
NeoForge, однако реальная загрузка и запуск этой версии ещё не проверены.
Лаунчер получает URL архива и SHA-512 через API Modrinth, а не доверяет
переданному URL напрямую. Проверку на чистой установке Windows всё ещё нужно
провести до публикации.

## Безопасность публикации source-релиза

При повторной установке лаунчер сначала собирает новый каталог релиза и только
затем переключает `current.json`: существующий релиз не удаляется до переключения.
Если идентификатор уже занят (в том числе повреждённой сборкой), используется
новый идентификатор; последующая очистка истории может удалить старые релизы
по обычной политике хранения. Идентификатор включает файлы сгенерированного
профиля загрузчика, а встроенные overrides проверяются до записи. Эти изменения
ещё требуют тестирования установки, отмены, восстановления и настоящего запуска
на Windows: синтетические тесты не заменяют такую проверку.

## Автоматическое сравнение packwiz

`npm test` преобразует общий тестовый packwiz-набор и сверяет ZIP с
`tests/fixtures/packwiz-parity/expected.json`. `cargo test` обрабатывает тот же
набор настоящим Rust-resolver и проверяет файлы через установщик, затем сравнивает
пути, размеры и SHA-256 с тем же манифестом. Данные загрузок подставлены из
тестовых файлов, без сети. Проверяются SHA-256 и SHA-512, обычный файл,
ресурс-пак, а также пропуск server-only и optional записей. Это не проверка
настоящего публичного пака, HTTPS, запуска Minecraft или полного цикла обновления.

### Проверка архива Modrinth без установки

Для сетевой диагностики с компьютера с доступом к Modrinth:

```powershell
npm run source:check-modrinth -- rQiXwLhB TQIsQXtg
```

Команда ищет версию в API проекта, скачивает `.mrpack`, сверяет SHA-512 с API
и выводит зависимости и количество файлов индекса. Данные ограничены по размеру;
профиль Minecraft она не изменяет. Это отдельная диагностика, а не проверка
установщика Rust: она не скачивает моды и не проверяет установку или запуск игры.
Для другого проекта укажите его ID и ID версии вместо приведённых значений.

При превышении лимита команда теперь указывает этап, размер и лимит: список
версий ограничен 4 МиБ, архив — 64 МиБ, как и в Rust-установщике. Если ошибка
относится к **архиву**, можно отдельно проверить больший архив, указав лимит в
МиБ (не более 512); архив хранится в памяти:

```powershell
npm run source:check-modrinth -- rQiXwLhB TQIsQXtg 256
```

Это увеличивает лимит только диагностической команды, не лаунчера; при архиве
больше 64 МиБ она выдаёт предупреждение и ненулевой код завершения. Не запускайте
её с большим лимитом при нехватке оперативной памяти. Если превышен лимит списка
версий, этот параметр не поможет: сообщите полный текст ошибки.

Для больших архивов диагностика допускает до 2 часов на HTTP-запрос и выводит
прогресс каждые 32 МиБ; для API остаётся 60 секунд. Она также выводит количество
`overrides/` и `client-overrides/` и сумму их **заявленных в ZIP** размеров,
считая оба слоя даже при совпадении путей, как это делает текущий установщик.
Это предварительная оценка: содержимое overrides команда не распаковывает и не
проверяет. Лимит установщика для них — 128 МиБ распакованных данных. Увеличение
времени ожидания диагностики не меняет ограничения или сетевые таймауты лаунчера.
