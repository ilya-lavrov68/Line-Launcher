# Диагностика скорости установки

Предел по умолчанию — 0 («без ограничения»). При этом тариф 100 Мбит/с означает теоретически около 12,5 МБ/с, а не 100 МБ/с; реальная скорость зависит от CDN, задержки, диска и нагрузки. Просмотр счётчика файлов не является измерением скорости сети.

У установки несколько этапов:

- `.mrpack` — один сетевой поток; размер и скорость ограничены отдающим сервером. Архив ещё проверяется и распаковывается.
- Файлы Modrinth/packwiz обрабатываются с максимумом в восемь одновременных задач, с немедленным заполнением освободившихся слотов. В это число входят и локальные `overrides`, которые копируются и проверяются, а не скачиваются. Лимит настройки общий для сетевых потоков, а не отдельный для каждого.
- Проверка, копирование и применение тысяч файлов зависят от диска и антивируса, а не только от интернета.
- Установщик Minecraft (`mc-launcher-core` 0.1.2) использует собственный механизм. В опубликованном исходном коде `execute_plan` загрузки идут последовательно; это возможное узкое место при тысячах мелких ресурсов. Этот механизм данным изменением не ускорен и настройкой скорости не ограничивается.
- При повторном запуске источника проверяются актуальные корневые метаданные и целостность релиза. Неизменная сборка повторно не скачивается. Для старой установки без сохранённой идентичности требуется повторное разрешение источника; при изменении источника или повреждении релиза сетевые файлы из предыдущего релиза повторно используются только после проверки по хешу и размеру из нового описания; остальные скачиваются. Overrides по-прежнему копируются из нового источника. Это не распространяется на загрузки Minecraft и установщика NeoForge.

## Как замерять

На Windows выберите «Без ограничения», запишите длительность и видимый этап каждого шага, а для сети — фактическую скорость процесса в диспетчере задач. Сравнивайте одинаковые сборку, версию, диск и условия (первую и повторную установку отдельно). Для проверки только установщика сборки есть ignored online тест BattleArmory; он не измеряет загрузку Minecraft и не запускает игру. Нельзя делать вывод о пропускной способности только по общему времени или количеству обработанных файлов.

## Диагностика повторных загрузок

В `launcher_logs/` записи `source file stage` содержат число файлов и байты успешно проверенных сетевых загрузок (`downloaded_files`, `downloaded_verified_bytes`), повторно использованных файлов (`reused_files`, `reused_bytes`) и локальных overrides/inline (`local_files`, `local_bytes`), а также длительность и результат. Это не счётчик трафика сети: служебные запросы, архив источника, заголовки и незавершённые загрузки в `downloaded_verified_bytes` не входят. При неизменённом источнике может появиться `source release cache hit` без `source file stage`.

Для Minecraft записи `minecraft preparation stage` показывают длительности этапов `pack`, `verify_and_sync`, `pack_safety`, `minecraft_and_loader` и успешность. При подготовке ZIP `pack.json` теперь запрашивается один раз на операцию, а не дважды; стадия `pack` включает этот запрос. Повтор после подтверждения по-прежнему является отдельной операцией и заново проверяет файлы. Отсутствующий этап означает, что до него не дошли или он не требовался. Эти записи не охватывают игровой процесс и не измеряют отдельно внутренние сетевые запросы Java-установщика. Они содержат только фиксированные названия, числа и флаг результата, без путей и адресов.

Сравнивайте первую подготовку и повторную с теми же настройками. Пришлите только эти строки и укажите, изменялась ли сборка. Если нужна проверка изменения одного файла, используйте отдельную тестовую сборку провайдера, не редактируйте вручную проверяемый релиз.
