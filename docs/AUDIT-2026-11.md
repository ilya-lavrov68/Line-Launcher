## Покрытие IPC-команд

В приложении 34 команды Tauri. Все зарегистрированы в `generate_handler`
(`src-tauri/src/lib.rs`) и все имеют клиента в `src/lib/line/api.ts` — расхождений
нет ни в одну сторону.

Из них **26 реально вызываются** в браузерном smoke-тесте. Не вызываются:

| Команда                                                              | Почему                                                                         | Статус                                                       |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------ |
| `cancel_install`                                                     | Отмена загрузки не автоматизирована в smoke                                    | логика прочитана, **проверено статически**                   |
| `rollback_release`                                                   | Откат релиза требует двух сборок в стабе                                       | **проверено статически** (3 Rust-теста)                      |
| `mc_install`, `mc_list_installed`, `mc_play`, `mc_stop`, `mc_status` | Панель режима Minecraft на странице сервера                                    | **проверено в браузере**: три состояния, прогресс, остановка |
| `mc_launch`                                                          | Не вызывается намеренно: запускает профиль без сверки с опубликованной сборкой | оставлен для будущего экрана выбора версии                   |

### Режим Minecraft: подключён как явный opt-in

Шесть команд `mc_*` были реализованы и протестированы, но не вызывались ни из
одного компонента: режим занимал место в бинарнике и ничего не давал игроку.
Теперь он подключён — и подключён **условно**, чтобы не мешать остальным.

Включается провайдером одной строкой: `"launch_mode": "minecraft"` плюс
`server_address` и `minecraft_version` (оба обязательны и проверяются при разборе
конфига). Конфиг без этого поля ведёт себя ровно как раньше: ни наличие адреса,
ни версия лаунчера не включают режим сами по себе.

На странице такого сервера панель Minecraft **заменяет** док-панель ZIP-сборки —
у режима нет провайдерского архива, поэтому кнопки установки и запуска ZIP там
всё равно не смогли бы работать. У серверов с `ticket` и `offline` панели нет.

| Команда             | Когда вызывается                                                   |
| ------------------- | ------------------------------------------------------------------ |
| `mc_status`         | при открытии страницы: «игра запущена» переживает смену экрана     |
| `mc_list_installed` | там же — счётчик готовых профилей (сбой чтения не показывается)    |
| `mc_play`           | «Играть»: проверка/загрузка → синхронизация → запуск с автозаходом |
| `mc_install`        | «Подготовить заранее»: скачать и проверить, не запуская            |
| `mc_stop`           | «Остановить игру»; фаза `exited` приходит событием, а не ответом   |

`mc_launch` в интерфейсе не используется намеренно: он запускает профиль без
сверки с опубликованной сборкой, и единственный корректный путь «просто играть» —
`mc_play`. Команда остаётся в API для будущего экрана выбора версии/загрузчика.

Проверено в браузере на конфиге с одним сервером режима `minecraft`: панель
показывает простое состояние, процент загрузки с подписью стадии, кнопку
«Остановить игру» после запуска и счётчик профилей. Обычный сервер после этих
изменений проходит тот же `npm run test:ui` без единой правки.

## Что нашлось и починено в этом проходе

Пять дефектов, каждый наблюдался в реальном браузере, а не выведен из чтения кода.

1. **Скин не загружался.** Палитровый PNG (colour type 3) отвергался как «не
   RGB/RGBA». Валидаторы в `wardrobe.rs` и `skin.ts` разрешали только типы 2 и 6.
   Теперь разрешены 2, 3 и 6 при глубине 8; серый (0/4) и 16 бит по-прежнему
   отвергаются. Проверено на исходном файле пользователя.

2. **Карточка сервера «прыгала» при наведении.** `whileHover={{ scale: 1.008 }}`
   плюс `transition-all` у общей кнопки приводили к пересчёту ширины текста
   (303 → 306 px) и переносу строки. Наведение теперь только поднимает карточку
   на 1 px, а переход ограничен цветом. Замер: `moved=0` элементов.

3. **«Остановить игру» запускала второй запуск.** Док на экране сервера отправлял
   любую фазу, кроме установки, в `onLaunch`. При запущенной игре кнопка
   «Остановить игру» звала `launch_game`, а не `stop_game`: игра продолжала
   работать, кнопка «Остановить» не исчезала. Исправлена маршрутизация по фазе.

4. **Имя скина затиралось.** `chooseFile` подставлял имя файла внутри
   асинхронного `arrayBuffer()`, поэтому имя, набранное после выбора файла,
   молча заменялось на `second.png` → «second». Подстановка перенесена в
   синхронную часть и срабатывает только для пустого поля.

5. **Все диалоги были во всю ширину.** Правило в `index.css` задавало
   `max-width: calc(100vw - 2.5rem) !important` для любого диалога, поэтому
   «О программе» открывалось шириной 1240 px, а `sm:max-w-[420px]` не мог
   победить. Правило убрано; «О программе» теперь карточка 384 px по центру.

Дополнительно по просьбе: нативные контролы (файловый пикер, числовые поля,
`<select>`) переведены на общую шкалу заполнений вместо системных «Choose File»
и чёрных стрелок; фон получил живой градиент с медленным дрейфом и палитрой,
выбираемой на этапе сборки.

## Что осталось непроверенным

Честно о границах этой среды:

- **Rust не компилировался.** Нет `rustc`/`cargo`, а crates.io недоступен, поэтому
  84 юнит-теста и весь граф зависимостей (tauri, reqwest, zip, tokio) не
  исполнялись. Правки в `wardrobe.rs` проверены логически и зеркальной
  TypeScript-реализацией, но **`cargo test` на реальной машине обязателен**.
- **Java-клиент** (`npm run test:java`) требует `javac` — не запускался.
- **Провайдер с собственным CA** (`npm run test:provider`) требует `keytool` —
  не запускался.
- **Windows-специфика**: заголовок окна, `WebView2`, найм окна, `taskkill` при
  остановке игры — проверяется только на Windows.
- **Настоящий запуск Minecraft** (скачивание, проверка подписи, JVM, вход на
  сервер) в этой среде невозможен: нет ни JDK, ни сети к Mojang.

## Рекомендации

1. Прогнать `cargo test` и `npm run test:rust` на машине с Rust — это
   единственный способ подтвердить правку валидатора скинов на стороне бэкенда.
2. Прогнать `npm run test:ui` на Windows: там же проверятся нативные контролы,
   которые в Chromium на Linux выглядят иначе.
3. Прогнать режим `minecraft` на машине с JDK и доступом к Mojang: интерфейс и
   контракт проверены, а реальная установка клиента и автозаход — нет.
4. Добавить `cancel_install` и `rollback_release` в smoke-тест: обе команды
   меняют состояние на диске, и обе сейчас проверены только чтением кода.
