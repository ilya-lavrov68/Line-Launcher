# Участие в Line Launcher

Line Launcher — source-available решение Plus In Plus для провайдеров игровых серверов, построенное на Obsy Launcher. Не добавляйте универсальные аккаунты, загрузчики, аддоны или произвольные JVM-настройки без отдельного архитектурного решения.

1. Создайте ветку от актуальной `main`.
2. Установите Node.js 22+, Rust stable и зависимости Tauri v2.
3. `npm ci`, затем `npm run tauri dev`.
4. Frontend-компоненты Line находятся в `src/components/line/`; переиспользуйте `src/components/ui/`, Tailwind-токены, Framer Motion, Lucide и Base UI.
5. Backend-команды не должны принимать секреты в логи, произвольные пути из JSON или токены в WebView.
6. Перед PR выполните `npm test`, `npm run build`, Rust fmt/test/clippy из README.
7. Перед **каждым** PR без исключений заново выполните `npm run screenshots`: проверьте полный набор из 14 скриншотов, всех шести GIF и шести постеров; обновите README, профильную документацию, `docs/VERIFICATION.md` и контрольные суммы `docs/visual-evidence.json`. Запустите `npm run visual-evidence:check`, отметьте каждый обязательный пункт шаблона PR и только затем открывайте PR. CI блокирует PR без этого аудита. Если реальный браузер/генератор недоступен, не открывайте PR с прежними изображениями.
8. Не прикладывайте пароли, токены, приватные конфиги и пользовательские миры к issue.
9. **Обновляйте документацию в том же изменении, что и код.** Проверьте README,
   профильные руководства, примеры и тестовые утверждения; помечайте старые
   результаты как исторические. Все незавершённые планы держите только в
   [docs/ROADMAP.md](docs/ROADMAP.md), а не добавляйте новые TODO/roadmap-файлы.
   При завершении задачи обновите её статус и удалите закрытую запись. Документы
   с историческими данными не выдавайте за текущее поведение.

Документация: [архитектура](docs/ARCHITECTURE.md), [контракт провайдера](docs/PROVIDER.md), [единый список работ](docs/ROADMAP.md), [брендинг](docs/BRANDING.md).
