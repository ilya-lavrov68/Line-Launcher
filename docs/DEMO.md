# Демо-режим: проверить лаунчер целиком

Одна команда поднимает **локальный демо-провайдер** и запускает **настоящее
приложение** — со входом, установкой, запуском Java-процесса, гардеробом и
настройками. Ничего не нужно вводить руками: адрес вшивается на время демо,
сертификат доверяется только этому процессу, при выходе всё возвращается как было.

```sh
npm ci
npm run demo
```

Первый запуск собирает Rust — это может занять несколько минут. Дальше окно
открывается само.

## Что нужно на компьютере

| Нужно                                                            | Зачем                          | Если нет                                                     |
| ---------------------------------------------------------------- | ------------------------------ | ------------------------------------------------------------ |
| Node.js 22+                                                      | всё остальное                  | поставьте Node                                               |
| Rust stable + [Tauri v2](https://tauri.app/start/prerequisites/) | собрать и открыть приложение   | `npm run demo -- --provider-only` поднимет только провайдера |
| openssl                                                          | локальный HTTPS-сертификат     | Windows: подойдёт openssl из Git for Windows, найдётся сам   |
| JDK 17+                                                          | демо-«игра» и проверка запуска | без него демо работает, но кнопка запуска честно выключена   |

Демо ничего не устанавливает в систему и не трогает хранилище сертификатов ОС.

## Что вы увидите

Проект называется **Line Demo (локально)**, аккаунт уже создан:
`Player_1` / `demo-password`. Можно зарегистрировать и свой — регистрация
работает по-настоящему.

| Сервер            | Для чего                                                                       |
| ----------------- | ------------------------------------------------------------------------------ |
| **Demo Survival** | полный цикл: установка → запуск → игра работает → остановить → история         |
| **Demo Creative** | второй сервер того же аккаунта: вход не спрашивается, сборка ставится отдельно |
| **Demo Showcase** | витрина без запуска: установка и гардероб есть, запуск не настроен             |

## Чек-лист: что нажимать

| Функция                     | Действие                                                      | Что должно произойти                                                      |
| --------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------- |
| Единый вход                 | войти один раз на экране аккаунта                             | открылся список из трёх серверов                                          |
| Один аккаунт на все серверы | открыть Demo Creative после Demo Survival                     | форма входа **не** появляется                                             |
| Установка                   | «Установить сборку»                                           | прогресс Downloading → Verifying → Extracting → 100 %                     |
| Запуск                      | «Играть»                                                      | статус «Игра запущена», в консоли провайдера `exchange accepted`          |
| Игра работает               | подождать                                                     | демо-«игра» живёт 20 секунд, пишет лог и завершается с кодом 0            |
| Остановка                   | «Играть», затем «Остановить игру»                             | процесс остановлен, статус «Игра завершилась»                             |
| Отмена запуска              | «Играть» и сразу «Отменить запуск»                            | запуск отменён, зависшей Java нет                                         |
| Обновление                  | `npm run demo:update` в другом терминале → «Переподключиться» | версия Demo Survival стала 1.1.0, кнопка установки снова активна          |
| Откат                       | «История сборок» → выбрать прежний релиз                      | возвращается 1.0.0 без повторного скачивания                              |
| Гардероб без входа          | открыть «Гардероб» до входа                                   | раздел работает, история пустая, файл выбирается                          |
| Автосинхронизация скина     | добавить `.provider/skins/demo-classic.png`                   | скин стал активным и ушёл на сервер сам, статус «отправлен автоматически» |
| Смена скина                 | добавить `demo-slim.png`, затем переключить активный          | каждый выбор уходит сам, кнопки «Отправить» нет                           |
| Стандартный скин            | выбрать «Стандартный скин»                                    | на сервере сброшено, локальная история цела                               |
| Повтор без сети             | остановить провайдера и сменить скин                          | выбор сохранён, статус «не удалось отправить»; после запуска повтор сам   |
| Настройки                   | память, Java, размер окна, «после запуска»                    | значения сохраняются после перезапуска                                    |
| Выход из аккаунта           | кнопка у логина слева внизу                                   | экран входа, список серверов закрыт                                       |
| Запуск не настроен          | открыть Demo Showcase                                         | установка есть, кнопка запуска выключена с пояснением                     |

Готовые текстуры лежат в `.provider/skins/` — искать PNG не нужно.

## Где смотреть, что произошло

- **Консоль провайдера** (там же, где вы запустили `npm run demo`): `login`,
  `register`, `ticket issued`, `exchange accepted`, `skin updated`, `skin reset`.
  Каждый отказ обмена пишется с причиной — это готовый оракул для проверки.
- **Лог игры**: `<app-data>/instances/<сервер>/logs/launch.log` — вывод самой
  демо-«игры», включая результат обмена. Перезаписывается при каждом запуске.
- **Данные лаунчера**: `<app-data>/instances/` — установленные релизы и история.

Каталог `<app-data>`:

| ОС      | Путь                                                            |
| ------- | --------------------------------------------------------------- |
| Windows | `%APPDATA%\studio.plusinplus.line-launcher`                     |
| macOS   | `~/Library/Application Support/studio.plusinplus.line-launcher` |
| Linux   | `~/.local/share/studio.plusinplus.line-launcher`                |

## Обновление и откат

Демо собирает два релиза Demo Survival. Пока провайдер работает:

```sh
npm run demo:update    # 1.0.0 → 1.1.0 и обратно
```

В лаунчере: «Переподключиться» → «Установить сборку» → «История сборок» → откат.
Предыдущий релиз остаётся доступным, поэтому откат проверяется по-настоящему.

## Проверка без окна приложения

```sh
npm run demo:check
```

Прогоняет весь контракт демо по настоящему HTTPS: схему конфига, опубликованные
хеши и размеры, оформление, один аккаунт на все серверы, гардероб, одноразовые
ticket и публикацию второго релиза. Нужны только Node и openssl — ни JDK, ни
Rust, ни окно. Полезно, когда `npm run demo` не запускается и надо понять, на
чьей стороне проблема.

## Если не работает

| Симптом                                    | Причина и что делать                                                                                         |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| «Окружение не готово… нет Rust»            | поставьте Rust stable и зависимости Tauri либо `npm run demo -- --provider-only`                             |
| «Провайдер не запустился на порту 8443»    | порт занят: `npm run demo -- --port 8453`                                                                    |
| «Компилятор Java не найден»                | демо без запуска игры. Поставьте JDK 17+ или задайте `JAVA_HOME`, затем повторите `npm run demo`             |
| В окне «Не удалось проверить сертификат»   | приложение запущено не через демо. Используйте `npm run demo` — он подключает сертификат сам                 |
| macOS: демо-сертификат не поддерживается   | добавьте `.provider/tls.crt` в System keychain ([RUNBOOK](RUNBOOK.md), 3.2) и запускайте приложение отдельно |
| Список серверов не грузится                | провайдер остановлен или порт другой; смотрите его консоль                                                   |
| Хочу начать с чистого листа                | остановите демо, удалите `.provider/` и каталог `instances` в app-data                                       |
| Хочу посмотреть только интерфейс, без Rust | `npm run test:ui` — сквозной прогон UI в Chrome/Edge с подменённым IPC (Rust не нужен)                       |

## Как это устроено

- `scripts/demo.mjs` — оркестратор: проверки окружения → сборки → брендинг →
  провайдер → приложение → возврат `branding/provider.json` при выходе.
- `examples/provider/build-pack.mjs` — три сервера, два релиза, оформление и
  готовые скины; всё детерминированно, без бинарников в репозитории.
- `examples/provider/server.mjs` — HTTPS-провайдер: вход, регистрация, гардероб,
  одноразовые ticket, обмен. Аккаунты в памяти, **не для production**.
- `examples/provider/publish-release.mjs` — публикует второй релиз на ходу.
- Cargo-фича `dev-provider-ca` добавляет локальный сертификат **только процессу
  лаунчера**. Она выключена по умолчанию и не должна попадать в распространяемую
  сборку; `npm run demo` никогда не собирает установщик.

Демо — разработка, а не образец безопасности: пароль сравнивается напрямую,
ticket лежат в `Map`, сертификат самоподписанный. Контракт протокола — тот же,
что у боевого провайдера: [PROVIDER.md](PROVIDER.md).
